# Wismail 批量定时发送 V2（mailcow 账号登录）

这是一个独立运行的 Wismail 网页模块，可与现有 mailcow 部署并存。V2 可通过 mailcow OAuth2 使用原网页邮箱账号登录；每位用户在模块中单独授权自己的发件邮箱。上传“一行一封完整邮件”的 Excel 或 UTF-8 CSV，检查后设置发送时间与间隔，由后台通过 SMTP 逐封发送。发送流程没有任何 AI API 调用，运行时不消耗 AI token。

## 已实现

- 下载 `.xlsx` 上传模板；导入 `.xlsx`、UTF-8 `.csv`。
- 检查收件邮箱、主题、正文、重复邮件及常见未填占位符；失败时指出表格行号。
- 导入后预览全部邮件；明确点击“确认并开始排队”才会发送。
- 按 UTC+8（可配置固定偏移）设置立即或定时开始、每封间隔、每小时和每日发送上限；支持暂停、继续、取消。
- 启动任务时可选填本批次每小时上限。它按最近 60 分钟已提交邮件计算，并与邮箱统一上限同时生效；留空仅使用邮箱统一上限。批次积压时，已达到上限的批次不会阻挡其他可发送批次。
- 不再联系名单：上传时拦截名单内邮箱；加入名单后，尚未发出的队列邮件会自动跳过。
- 逐封记录待发送、发送中、已提交发信服务器、失败、需人工核对；批次统计和 CSV 明细导出。
- 批次详情显示发送流程和已处理进度：草稿检查、计划排队、SMTP 提交、后续反馈，并标出待重试、失败和需人工核对的数量。已处理包含取消和不再联系邮件；它不是送达率。实际发送可能因限速晚于计划。
- 统计报表：按日期、月份、实际发件地址及批次汇总 SMTP 提交、当前发送失败、IMAP 检测到的退信与回复；历史邮件未记录发件地址时单列为“未记录发件地址”。可导出 CSV，或用浏览器打印/保存 PDF。批次页面显示最近 30 条发送事件和 SMTP 返回码，并可导出全部事件 CSV。
- 可选 IMAP 同步：依据邮件头关联回复；依据退信报告或唯一匹配的收件地址关联退信。未能匹配的来信只记为未匹配事件，不会错误标记某封邮件。
- mailcow OAuth2 登录、每个邮箱自己的应用密码、按邮箱隔离批次和发送统计；可随时撤销授权，撤销后该邮箱未完成的批次暂停。
- 联系人库：每邮箱独立的联系人、分类、姓名/性别/生日/手机/地区和 10 个自定义变量；支持 CSV/XLSX 导入同邮箱合并、搜索、筛选、CSV 导出和回收站。导入文件中邮箱大小写归一后自动去重，互补字段及分类合并，同一非空字段冲突会拒绝整份文件；再次导入的空字段不会清除已有资料。可手动创建、重命名、删除分类，并给联系人添加或移除分类。重命名会同步更新自动化规则引用；规则正在使用的分类不可删除。还可将同一账号下两个不同邮箱联系人手动合并：主联系人保留已填写资料，空字段从次联系人补齐，分类取并集，较严格的禁止发送状态保留；次联系人保留原邮箱记录并归档，排队邮件会被拦截。已合并的次联系人不能直接恢复，合并不能自动拆分。重新导入不会清除退订、投诉、无效或归档状态。
- 操作日志：登录后可查看当前账号最近 100 条成功操作，涵盖授权、模板、联系人、自动化和批次管理；只记录动作、时间及相关批次编号，不保存密码、邮件正文或上传内容。历史操作不会回填，登录失败和 SMTP 后台发送事件分别由认证系统及发送日志处理。
- 账号内提醒：从已有逐封事件中显示当前账号最近 100 条发送失败、需人工核对及 IMAP 检测到退信；可以分别关闭这两类提醒并逐条标为已读。关闭只影响页面显示，不会改变发送记录或禁发规则。提醒不额外发送邮件；旧事件如仍在逐封事件表中也会显示。
- 不再联系名单管理：首页可进入完整名单，搜索本账号及全局禁发地址并导出 CSV；页面显示最近 200 条，导出包含全部。只允许移除本账号标为手动添加的项目；非手动来源和全局禁发项不可通过此操作移除。移除手动项不会恢复联系人禁发状态或已经拦截的排队邮件。再次手动添加已有地址不会覆盖原来的禁发原因。
- 邮件模板：主题、纯文本及可选 HTML 正文；每次保存保留历史版本。可使用联系人变量预览，按分类创建待确认批次。批次创建时固定展开内容，后续改动模板不会改变已创建的邮件。测试邮件只允许发往当前发件邮箱，需显式确认。
- 模板页可将当前显示的历史版本复制成独立的新模板，从 v1 开始编辑。选取联系人后可查看纯文本和隔离的 HTML 效果预览；预览不运行脚本、不提交表单，也不加载外部图片。实际邮件显示仍取决于收件人的邮箱客户端。
- 模板页可对已保存的当前显示版本和一个选定联系人运行发送前预检测：检查变量缺值或残留、过长主题、常见不兼容 HTML 标签、异常链接及图片替代文字。检测不访问外链、不发送邮件，也不预测收件箱送达率。历史版本的预览和测试发送使用当前显示的版本；若要用历史版本创建任务，需先复制成新模板。
- 新模板默认可在可视化模式编辑 HTML：标题、加粗、斜体、列表和绝对 HTTP(S)/mailto 链接；纯文本正文仍需单独填写。已有模板默认显示 HTML 源码，切换到可视化模式前会提示不支持的元素或属性可能被移除，取消切换可保留原源码。粘贴只导入纯文本；保存后仍需选择联系人预览并核对实际邮件效果。
- 联系人任务筛选：包含/排除分类、邮箱字符包含/排除、排除最近已提交过邮件的联系人，以及最近观测到打开/点击的联系人。预览不会建立批次；创建草稿时重新筛选，最终名单以草稿页为准。每批可选 1 至 5 个模板，按联系人顺序轮流使用，并记录每封邮件使用的模板名称和版本。
- 自动化规则：账号本人可为首次观测打开、首次观测点击、收件人确认退订或联系人生日创建“加入分类”规则；打开、点击和生日可选择本人保存的模板生成一封待确认草稿。生日规则必须选择模板，按 `WISMAIL_UTC_OFFSET_HOURS` 对应的本地日期检查，每位联系人每条规则每年最多触发一次；2 月 29 日只在闰年触发。另可创建指定日期（自定义 MM-DD）、每周（周一为 1）和每月（1–31）规则，只针对指定联系人分类生成草稿；短月份不会顺延，每位联系人每条规则在同一本地日期最多生成一次。退订不能生成草稿，退订或不再联系名单中的联系人不会生成草稿。规则可暂停、启用、删除，并查看最近触发和草稿结果；默认没有规则，草稿不会自动发送，必须由用户检查并启动。打开和点击可能由代理或安全扫描触发。删除规则不会移除已生成的草稿。指定日期由用户维护，不包含自动更新的法定节假日日历。
- A/B 对比模式须恰好选 2 个模板和至少 2 位联系人。按联系人邮箱、账号、模板及任务名称生成稳定的散列顺序，再均衡分配 A/B；联系人名单不变时，预览和创建结果一致。批次详情显示两组提交、打开、点击、点击率、退信与回复。只有两组各至少 30 封已提交、任务已完成、最后一封提交满 24 小时且启用点击记录时，才用 [NIST 介绍的 Wilson 95% 区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm) 给出保守的模板选择提示；区间重叠时不选。该提示不会自动改变发送计划，点击可能来自安全扫描。
- 批次详情可将已有任务的收件人、主题、正文及模板版本快照复制为新草稿。新草稿不继承发送时间、发送状态、回复地址、每小时上限、A/B 模式或打开/点击跟踪设置；复制时重新检查退订、投诉、无效、回收站和不再联系名单，存在禁止发送地址时拒绝整批复制。复制后须重新核对并手动启动。
- 批次启动前可填写同发件邮箱域名的回复地址；留空时使用发件邮箱。该地址写入邮件 `Reply-To`，不改变 SMTP 发件人。回复发往其他邮箱时，本账号的 IMAP 回复统计可能无法识别。复制任务不会继承回复地址。
- HTML 邮件可在启动批次时单独勾选打开或点击记录。打开使用签名图片地址；点击只重写绝对 HTTP/HTTPS ASCII 链接，并使用签名跳转地址。Wismail 数据库仅保存每封邮件首次观测时间，不保存请求 IP；前置 Nginx 的访问日志仍可能记录请求信息。默认不启用；纯文本邮件不支持。
- 发送保护：导入批次和实际发送前均检查联系人状态及不再联系名单；被拦截的排队邮件标记为不再联系。已配置 HTTPS 网站地址及会话密钥时，外发邮件包含签名退订链接，收件人确认后加入不再联系名单。IMAP 退信报告同时明确包含原邮件 Message-ID、相同收件地址、`Action: failed` 和 `Status: 5.x.x` 时，会将本账号地址加入不再联系名单，把可发送联系人标为无效，并拦截未发送邮件；临时退信或仅靠地址猜测匹配的退信只记入报告。联系人页可手动导入已核对来源的投诉/无效地址 CSV，格式为 UTF-8 `邮箱,类型`，类型只能是 `投诉` 或 `无效地址`。导入会创建或更新本账号联系人、加入禁发名单、拦截排队邮件，按文件 SHA-256 避免重复处理，并记录来源和逐行结果；错误行会拒绝整份文件。来源名称由上传者填写，系统不会验证文件是否确实来自服务商；服务商 API 或推送回调仍未接入。
- 应用密码由服务器密钥加密后保存；CSRF 校验、上传大小限制。保留原有单管理员模式供未配置 OAuth2 的本地环境使用。

## 使用流程

在“发件授权”页面可验证 mailcow 已授予当前邮箱 send-as 权限的代发地址。Wismail 使用当前邮箱的 SMTP 应用密码执行 `MAIL FROM` 和 `RCPT TO` 授权检查，不提交 `DATA`，因此不会发出测试邮件；验证通过后只保存地址与验证时间，不保存额外密码。待确认批次可勾选当前邮箱及已验证地址，启动时重新验证代发权限，随后按所选顺序逐封轮用。所有邮件仍使用当前邮箱的 SMTP 登录和邮箱级限速；移除代发地址会暂停仍有该地址待发送邮件的批次。mailcow 权限若被管理员撤销，SMTP 仍会拒绝该地址后续发送。

1. 使用现有 Wismail/mailcow 网页邮箱账号登录模块；第一次使用时到“发件授权”填写该邮箱的 SMTP 应用密码（可选填 IMAP 应用密码）。模块验证登录，不发送测试邮件。
2. 可打开“邮件模板”创建主题和正文，再在“创建任务”中筛选联系人、选择一个或多个轮用模板并预览；也可从首页下载 Excel 模板。Excel 第一行是固定列名：`收件邮箱`、`邮件主题`、`邮件正文`。从第二行开始，一行一封完整邮件。
3. 上传文件。Wismail 检查并显示逐封预览；有错误则拒绝创建批次。
4. 选择立即开始或设置开始时间、发送间隔；如果全部邮件都有 HTML 正文，可按需要勾选打开/点击记录。再点击“确认并开始排队”，后台到点以当前用户的邮箱提交邮件。
5. 在批次页面查看统计、逐封状态和发送日志，必要时暂停、取消或导出明细。打开“统计报表”可选择日期范围查看按日、月、发件地址及批次汇总。其他用户看不到本邮箱的批次和报表。

联系人页面可添加、导入、筛选和导出联系人。导入表头至少包含“邮箱”；可选“姓名、性别、生日、手机、地区、分类、变量1…变量10”。分类用逗号分隔，每次最多 1000 人。退订链接使用 `WISMAIL_SESSION_SECRET` 签名，并以 `WISMAIL_OAUTH_BASE_URL` 和 `WISMAIL_URL_PREFIX` 拼接公开地址；上线前须确认两者指向实际 HTTPS 站点。

模板变量包括 `{{邮箱}}`、`{{姓名}}`、`{{性别}}`、`{{生日}}`、`{{手机}}`、`{{地区}}` 和 `{{变量1}}` 至 `{{变量10}}`。若目标联系人缺少用到的变量，整个批次创建会被拒绝。联系人任务仅包含可发送且未退订、未删除、未在不再联系名单中的联系人，每批上限 1000 人。排除近期已提交的条件使用 SMTP 接受时间，不代表实际送达；打开/点击条件使用首次请求时间，可能受到代理和安全扫描影响。`WISMAIL_HOURLY_LIMIT` 默认每邮箱每 60 分钟 20 封；它与每日上限及每封最短间隔同时生效。测试发送会实际提交一封邮件，只有操作人确认后才会执行。

## 启动

推荐 Docker Compose（Python 3.12）。本地运行也建议使用 Python 3.12，并安装 `requirements.txt`。先复制环境变量文件：

```powershell
Copy-Item .env.example .env
```

### 1. 在 mailcow 注册 OAuth2 客户端

在 `https://mail.wiskind.top/` 的 mailcow 管理页面 **Configuration → Access → OAuth2** 新增客户端，回调地址填写 **`https://mail.wiskind.top/bulk/oauth/callback`**。记录客户端 ID 和密钥。mailcow 官方的 [OAuth2 接入说明](https://docs.mailcow.email/third_party/nextcloud/third_party-nextcloud/) 展示了相同的注册流程与 `/oauth/authorize`、`/oauth/token`、`/oauth/profile` 接口。已通过只读网络检查确认该站点和 OAuth 身份接口可访问；尚未在实际管理员后台注册客户端。

### 2. 设置模块密钥和服务器地址

生成两个不同的长期密钥，填入 `.env`：

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

第一行用于 `WISMAIL_CREDENTIAL_KEY`，第二行用于 `WISMAIL_SESSION_SECRET`。这两个值必须长期保留；丢失凭证加密密钥后，已保存的应用密码无法解密，需要用户重新授权。

`.env.example` 已填好 `https://mail.wiskind.top`、`/bulk` 回调，以及同主机的 SMTP 587 与 IMAP 993 地址。只读 TCP 检查确认这两个端口可连接。仍需填写 OAuth 客户端 ID/密钥和两项长期密钥。所有 OAuth2 项必须一起配置，且 OAuth2 地址必须使用 HTTPS。

### 3. 启动与访问

从本 GitHub 分支部署时，源码位于 `mailcow-dockerized/wismail-bulk-sender`；仓库根目录的 `docker-compose.override.yml` 已指向该目录，并读取 `wismail-bulk-sender/.env`。请在服务器上单独创建 `.env`，不要提交到 Git。仓库已包含 `data/conf/nginx/site.bulk.custom` 和 `data/web/inc/vars.local.inc.php`；如果服务器上已有同名自定义文件，应合并内容，不要直接覆盖。

在服务器的 `mailcow-dockerized` 目录运行：

```bash
docker compose up -d --build wismail-bulk-sender
docker compose exec nginx-mailcow nginx -t
docker compose restart nginx-mailcow php-fpm-mailcow
```

然后打开 `https://mail.wiskind.top/bulk/`。模块会跳转到 mailcow 登录，再返回批量发送页面。`site.bulk.custom` 使用 mailcow 官方支持的 `site.*.custom` 扩展方式；如站点前还有一层反向代理，须确保 `/bulk/` 请求原样转发给 mailcow。详见 [mailcow 自定义站点文档](https://docs.mailcow.email/manual-guides/Nginx/u_e-nginx_custom/)。

Python 本地启动时，`.env` 不会自动加载；需要在当前进程环境中设置相同变量。未配置 OAuth2 时仍可使用旧版单管理员模式，例如：

```powershell
$env:WISMAIL_ADMIN_PASSWORD = '替换为至少12位的随机密码'
$env:WISMAIL_SMTP_HOST = 'smtp.example.com'
$env:WISMAIL_SMTP_PORT = '587'
$env:WISMAIL_SMTP_USER = 'sales@example.com'
$env:WISMAIL_SMTP_PASSWORD = '邮箱应用密码'
$env:WISMAIL_SMTP_FROM = 'sales@example.com'
python server.py
```

本地单管理员模式通过 `http://127.0.0.1:8765` 访问；此模式仍使用服务器环境变量中的一个固定发件账号。不要将未加 HTTPS 的端口直接暴露到公网。

OAuth2 模式下，每个用户只能授权与自己登录身份相同的发件邮箱；SMTP/IMAP 服务器地址由管理员统一配置。启用双重验证的 mailcow 邮箱通常需要创建应用密码供 SMTP/IMAP 使用；网页登录密码不会交给定时任务。不同外部邮箱服务商的单独 OAuth 授权尚未实现。

管理员配置 IMAP 服务器地址、用户在“发件授权”中填写 IMAP 应用密码后，模块每两分钟读取一次该邮箱 INBOX 来识别回复或退信。第一次连接会从较早邮件开始读取，逐步推进；识别属于“尽力匹配”，具体效果取决于服务商保留的邮件头及退信格式。旧版单管理员模式仍通过环境变量配置 IMAP 用户与密码。

## 统计口径与限制

- **已提交**：外部 SMTP 接受了 Wismail 的邮件提交。它不代表对方服务器接受，更不代表进入客户收件箱。
- **日期范围**：按配置的固定时区计算事件发生的本地日期，最多查看连续 366 个日历日。报表中的退信/回复是所选日期内检测到的事件，可能属于更早提交的邮件。失败只计当前仍处于失败或待核对状态、且最后一次尝试落在范围内的邮件。不同指标因此不应直接相除当作投递成功率。
- **退信 / 回复**：只有配置并成功读取 IMAP，且能可靠关联原邮件时才标记。无数据不等于零退信或零回复。
- **观测打开 / 点击**：只针对主动启用跟踪的 HTML 批次记录每封邮件首次请求。图片代理、预加载和安全扫描可能触发这些请求；关闭图片或不点击则不会有记录。纯文本链接、邮件退订链接不纳入点击记录。数字不能当作真实阅读或点击人数。
- **发送日志**：此功能上线后新发生的 SMTP 提交、失败、重试和 IMAP 匹配才写入逐封事件表；旧邮件继续显示已有状态和时间。具体失败原因以 SMTP 返回信息为准。
- 本版不提供“打开 IP / 客户所在地”统计。邮件应用可能通过代理加载图片或提前加载，结果不能可靠代表客户所在地。
- SMTP 成功后的邮件保存在 Wismail 批次明细中；是否出现在外部邮箱的“已发送”文件夹取决于服务商，本版不主动写入该文件夹。
- 本版已支持 mailcow 账号登录、每个登录邮箱的独立发信授权、可选 HTML 正文和已验证代发地址轮换。尚未接入 mailcow 角色管理、附件、不同外部邮箱服务商的 OAuth 授权或最终投递日志 API。代发地址轮换只使用当前邮箱的 SMTP 登录，不借用其他邮箱的凭证。
- 同时只运行**一个**应用实例。SQLite 和后台任务线程目前不支持水平扩容。

## 安全与运维

请使用服务商允许的联系人名单，发送前核对 AI 生成的产品、价格和承诺。需要长期运行时应备份 `data/wismail.sqlite3`；这里存有邮件正文、收件信息和加密后的应用密码。请限制谁能访问该数据库与 `.env`。本版对处于“发送中”时突然中断的邮件标记为“需人工核对”，不会自动重发，避免重复投递。
